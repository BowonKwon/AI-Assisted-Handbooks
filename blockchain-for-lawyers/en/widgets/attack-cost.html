Chapter 20 · The security budget

How long does an attack take, and what does it cost?

How many blocks, in expectation, it takes an attacker who brings A times the honest side's hash rate to overturn k + e blocks (Budish, Proposition 3), and what it costs to run that hash rate for that time. The coin price enters nowhere. The reader enters the unit price c, and this book gives no value — leave it out and the cost comes out as "a number of block rewards."

What this calculator does not give

  • Coin prices, electricity unit prices, equipment rental. The unit of the cost is decided by what the reader enters as c. Enter half the unit price and the cost halves — what this calculator tells you is a proportion, not a level (Chapter 20, Section 5).
  • The value obtained by attacking. Budish's equation (3) asks about the ratio of the reward pblock to the value of an attack, but this figure draws only the cost side. The case in which the net cost can be 0 (when the attacker keeps the block rewards) is in Chapter 20, Section 4.
  • The hash rate H is an estimate computed from the reference-date difficulty as D·2³²/600, not a measurement. If the block interval differs from 600 seconds, it is off by that much (data/README). It differs by about 7% from the comparison value (the figure published by an explorer).
  • Proposition 3 assumes that the attacker "can bring" additional hash rate. The specialized-capital model, for when inventory (ASICs) is at stake, is in Chapter 20, Section 7.
