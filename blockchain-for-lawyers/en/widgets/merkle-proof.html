Chapter 6 · Merkle trees

You only need to remember your opponents

The n transactions are paired two at a time up to a single root. To show that one transaction is included, one sibling hash per level from leaf to root, ⌈log₂ n⌉ in all, is enough. Increase the number of transactions and see how much the proof grows.

proof length = ⌈log₂ n⌉ hashes = 32·⌈log₂ n⌉ bytes · on a level with an odd count, the last one is used once more to make a pair · H = one SHA-256 (general form)

How this tree differs from Bitcoin's tree

  • Here SHA-256 is applied once. Bitcoin applies it twice (double SHA-256), and the leaves are txids (Chapter 6, Section 4, NB06-3).
  • The rule of duplicating the last hash on a level with an odd count is the same as Bitcoin's. That rule created the weakness by which different transaction lists can produce the same root (CVE-2012-2459) — Chapter 6, Section 4.
  • A proof guarantees only that "this transaction is under this root." That the root belongs to a real block is guaranteed by the header hash of Chapter 7 and the proof of work of Chapter 8.
