Tampering shows, but re-threading is free

A toy chain of six blocks without proof of work. Change the transaction in one block and that block's hash changes, so it no longer matches the "previous hash" recorded by the next block. Yet rewriting every block after it takes only one hash per block.

What this chain lacks

  • There is no proof of work, so "re-threading" takes one hash per block. Chapter 8 adds one line to this class, "raise the nonce until the first k bits of the hash are 0," and so makes re-threading costly.
  • When both chains are valid, there is no device that tells which one is the original (NB07-2). What a hash chain guarantees is consistency, not history.
  • The transaction enters the header only as a single value, SHA-256(transaction). Real Bitcoin puts the Merkle root (Chapter 6) in that place.
